# v1.0検証: AI-A ↔ AI-B 最小往復

`v1.0-goal.md` の検証方法のうち「このセッションと別のAIエージェントがAMPで多ターン往復する」
を実施した記録。

## 方法

MAGIのような複合システムを経由せず、AMP単体を検証するため最小構成にした。
`entity:agent.a`(AI-A)役・`entity:agent.b`(AI-B)役をそれぞれ**独立したコンテキストの
サブエージェント**(Agent tool、`general-purpose`)に演じさせ、1ターンごとに新規に呼び出した。
各サブエージェントは相手が何を考えているかを一切共有されず、`spec/01-v0.1仕様.md`・
`examples/v1-roundtrip-catalog.json`・受け取ったJSON(と会話履歴)だけから次のAMPメッセージを
自分で組み立てた。オーケストレーター(このセッション)はJSONを右から左に中継し、各ターンで
`amp render`による構文検証を挟んだだけで、内容には一切手を入れていない。

カタログ: [`examples/v1-roundtrip-catalog.json`](../examples/v1-roundtrip-catalog.json)
メッセージ: [`examples/v1-roundtrip-messages.jsonl`](../examples/v1-roundtrip-messages.jsonl)

## 結果

```
$ amp render --catalog examples/v1-roundtrip-catalog.json examples/v1-roundtrip-messages.jsonl
AI-A requests AI-B to send file.a to AI-A.
AI-B will send file.a to AI-A.
Did AI-B send file.a to AI-A?
AI-B sent file.a to AI-A.
AI-A ends the conversation.
```

5メッセージ全て構文的に妥当(exit 0)。人間が読んで意味の破綻なく会話を追える。

## v1.0の5条件との照合

1. **3往復以上、AI自身がJSON生成** — ✓。`request`→`commit`→`query`→`inform`→`close`の
   5メッセージを、5回とも独立したサブエージェントが自分で組み立てた。人間(このセッション)は
   一度もcontentの中身を書いていない
2. **意味的一貫性** — ✓。特にmsg-003が効いている。AI-Aはmsg-002(commit)を踏まえて
   「まだfile.aを受け取っていない、本当に送ったのか」という**状態を参照したquery**を
   自発的に生成した。前のターンを無視した無関係な発話は一度も起きなかった
3. **`amp render`で英文監査可能** — ✓。上記の5行がそのまま監査ログとして成立する
4. **独立実装でなくてよい** — ✓。4回のサブエージェント呼び出しはどれも新規コンテキストで、
   相手の意図を直接共有していない。生成→送信→解釈→応答のラウンドトリップの検証にはなった
   (相互運用性の検証にはならない。それは判断書の言う次のフェーズ)
5. **静的カタログ前提** — ✓。handshakeなし、事前に用意した5エントリのカタログのみ使用

## 気づいた点

- **AI-Bは要求を無条件で受け入れなかったわけではなく、判断した**: msg-001を見て
  `reject`/`failure`も選択肢としてあったはずだが、要求が正当と判断して`commit`を選んだ。
  プロンプトは「要求を受け入れるかどうかもあなたの判断」とだけ伝えており、`commit`にしろとは
  指示していない
- **`close`のcontentにpredicateを含めてもエラーにならない**: spec §9.4は
  「`content.roles`は取らない(あれば`UnsupportedRole`)」としか書いておらず、`predicate`自体の
  可否は明記していない。AI-Aは`{"predicate": {"lemma": "end", ...}}`を自発的に付けたが、
  実装はこれを許容し、固定文言"ends the conversation."を出した(predicateの中身は使われて
  いない)。仕様の記述漏れ、実害なし
- **リトライは一度も発生しなかった**: 5回のサブエージェント呼び出し全てが一発で構文的に
  妥当なJSONを生成した。仕様書とカタログを読ませるだけで、AIが仕様に従ってAMPを書けることの
  再現性は今回の1回では判断できないが、少なくとも失敗しなかった

## 結論

`v1.0-goal.md` の5条件を満たした。**AIは実際にAMPを生成し、AMPを読んで状態を保持しながら
会話を継続できる。** M6(MAGI dogfooding)が残していた「人間がJSONに変換しただけ」という
ギャップはここで埋まった。

次のフェーズ(v1.0-goal.mdの「達成後」)は判断7の対象だったMAGIへの組み込み。今回の結果により、
「AMPが動くか」と「MAGI全体が動くか」を切り分けて評価できる状態になった。
