# 実験F: 意味取り違え率の直接比較(自然言語 vs AMP)

v2-goal-necessity-proof.mdが掲げた最終目標そのものを検証する実験。実験C・D・Eが
示した「表現できない領域(条件節)」とは別トラックとして、**AMPが表現できる範囲
(agent/patient/recipient/act/predicate/tense)に限定**し、そこで自然言語と
AMPのどちらが意味の一意性を保てるかを直接比較する。「AIが正解したか」だけでなく
「複数の解釈が成立したか」を測る、というユーザー指定の評価軸を採用した。

## ケース1: pronoun照応(複数ファイルの中でどれを指すか)

**背景**: AI-Aは過去にAI-Bとfile.a・file.bの両方について話したことがある。
今回望んでいるのはfile.aだけ。

**条件N(自然言語)**:
- A発話: "Hey, can you send over that first file we were talking about now?
  No need for the other one right now, just that one is fine."
- B役の解釈: `INTERPRETED_FILE: file.a` / `CONFIDENCE: 低い` /
  `MULTIPLE_INTERPRETATIONS_POSSIBLE: はい`——
  「"file.a"という命名は最初に言及された可能性を示唆する弱い手がかりに過ぎず、
  実際の会話順序の記憶がない以上file.bが先だった可能性も同程度に残る」

**条件A(AMP)**:
- A役が生成: `content.roles.patient.refs = ["entity:file.a"]`
- B役の解釈: `INTERPRETED_FILE: file.a` / `CONFIDENCE: 高い` /
  `MULTIPLE_INTERPRETATIONS_POSSIBLE: いいえ`——
  「`refs`はカタログ上の具体的なentity IDを直接指定する仕様であり、自然言語の
  代名詞のような文脈依存の曖昧さが構造的に排除されている」

## 結果

| 指標 | 条件N(自然言語) | 条件A(AMP) |
|---|---|---|
| 対象ファイルの正解 | file.a(一致) | file.a(一致) |
| confidence | 低い | 高い |
| 複数解釈の可能性 | **あり** | **なし** |

**正解率だけでは差がつかない(1/1 vs 1/1)。** しかし、これこそがこの実験の
核心的な発見: B役は自然言語条件でたまたま正解しただけで、**自分でもそれを
「低いconfidence」「複数の解釈が可能」と認識していた**。正解したかどうかを見る
だけの評価では、この違いを見逃す。ユーザーが最初から指摘していた
「AIがたまたま正解する」と「構造上、別の意味に解釈しにくい」の違いが、
自己申告という形で直接観測できた。

## 意義(1ケースの結果として、慎重に)

**まだ「AMPが自然言語より優れる」とは言わない。** これは1ケースの結果であり、
言える範囲は次まで:

> このケースでは、正解率が同じ(1/1 vs 1/1)でも、AMPの方が解釈の
> 不確実性を低くできた。

「AMPは意味取り違えを減らす」という一般的な結論にするには、この差を
複数ケースで再現する必要がある。実験の厳密性としてここは重要——1件の
成功で強い主張をするのは、まさにこのプロジェクトが避けようとしてきた
(ADR-024, 判断書の哲学)拙速な一般化そのものになる。

## 次にやるなら: 実験F-2(表現揺れ・参照揺れ耐性)

10〜20ターンの実験G(長期マルチターン)にいきなり進むより、まずFを
横方向に増やすべき。実験Cは「AMP生成側が4つの言い回しを同一構造に
収束させるか」を見た。F-2は一歩進めて、**その収束した構造がAI-B側の
解釈安定性にもつながるか**を見る——同じ意味を自然言語では複数の異なる
言い回しで表現し、それぞれについてB側の意味一致・confidence・複数解釈
可能性を測定し、ばらつきの有無を確認する。

F-2で差が複数ケースにわたって再現して初めて、実験G(長期マルチターン、
参照の意図的な混乱)に進む価値が出る。
