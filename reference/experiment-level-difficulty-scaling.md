# 難易度別スケーリング実験: entity参照問題の段階的検証

ユーザー提案の難易度レベル(Level1〜4)に沿って、実験F/F-2/Gの知見を段階化し、
「自然言語の曖昧性が増すにつれてAMPとの差がどう変化するか」を見た。

## Level 1: 2entity + 指示語(実験F・F-2の要約)

- 実験Fケース1(pronoun照応、1ケース): 正解率同じ(1/1)、confidence 低い→高い
- 実験F-2(表現揺れ、4ケース): **正解率自体に差**(自然言語1/4、AMP実質4/4)

→ 詳細は[experiment-f-mismatch-rate.md](experiment-f-mismatch-rate.md)、
[experiment-f2-reference-stability.md](experiment-f2-reference-stability.md)

## Level 2: 3entity + 複数ターン(実験Gの要約)

競合する手がかり(直近性 vs 動詞の意味的対応)を含む7ターンの会話で、
正解率同じ(1/1)、confidence 中程度→高い、複数解釈可能性 あり→なし。

→ 詳細は[experiment-g-longterm-reference.md](experiment-g-longterm-reference.md)

## Level 3: 同一entityの反復参照(新規)

file.aが2回、異なる宛先(AI-A自身/Carol)向けの文脈で登場する場合の"it"の解決。

**試行1(失敗)**: 最初の送信を"Sent"(完了済み)にしたところ、「完了済みの
依頼を再確認する意味がない」という語用論的推論が働き、両条件とも正解・高
confidence・曖昧性なしで差が出なかった。

**試行2(成功)**: 両方の送信を"I'll send it"(未完了・commitのみ)にすると:

| 指標 | 自然言語 | AMP |
|---|---|---|
| 実際の正解(AI-A自身宛て) | ✗(直近性からCarol宛てと推論、**逆方向**) | ✓ |
| confidence | 中程度 | 高い |
| 複数解釈可能性 | あり(自己申告) | なし |

自然言語版は「直近性の原則に従えばCarol宛てへの確認である可能性が高いが、
AI-A自身への未解決タスクとの間で曖昧性が残る」と回答した——これは
Level1・2で見た「confidenceが下がる」だけでなく、**間違った方向に
バイアスされうる**ことを初めて示した。

## Level 4: 属性ベースの参照(新規、差が出ず)

3つのファイルがそれぞれ異なる曜日に登場し、「昨日送ったファイル」という
時間属性で後から参照するケース。

**結果**: 両条件とも正解(file.b)、confidence高い、曖昧性なし——**差が
出なかった**。

原因: 各ターンに曜日(Monday/Tuesday/Wednesday)を明示していたため、
「今日はWednesday、昨日はTuesday、Tuesdayの話題はfile.b」という単純な
日付計算だけで一意に解決できてしまった。真の属性ベースの曖昧性
(例: 複数のファイルが同じ属性を共有する、日付情報自体が会話に明示的に
現れない)を作れていない——**Level3までとは異なり、これは設計不足による
失敗であり、「差がない」という結論を意味しない**。

## 全体傾向(暫定)

| Level | 差の大きさ | 備考 |
|---|---|---|
| 1(指示語, 2entity) | 中〜大(F-2で正解率に差) | 表現の種類による |
| 2(複数ターン, 3entity) | 中(confidence/曖昧性に差) | 正解率は同じ |
| 3(同一entity反復, 未完了状態) | **大**(方向性まで逆転) | 最も明確な差 |
| 4(属性ベース) | 未検証(設計不足) | 再設計が必要 |

**現時点で言えること**: entity数や会話の長さそのものより、**「複数の
未解決タスク・候補が並行して存在し、直近性のような表面的な手がかりが
本来の対象と一致しない」状況**で、AMPと自然言語の差が最も大きくなる
(Level 3)。単に「情報が多い」「ターンが多い」ことは、それだけでは
差を拡大しない(Level 4は情報が最も多いが差が出なかった)。これは
ユーザーが当初から警告していた「長いコンテキストの記憶力の実験になる罠」
を裏側から確認する結果でもある——差を生むのは長さではなく、**手がかり
同士の競合・対立**である。

## 次にやるなら

- Level 4を、日付情報を会話から隠す(またはtimestampを共有しない)形で
  再設計し、真の属性ベースの曖昧性を作る
- Level 3のパターン(未解決タスクの並行存在)をentity数3・4に拡張し、
  「対象が増えるほど差が拡大するか」を見る
- ここまでの結果はすべて同一モデル(Sonnet)・同一会話設計者(このセッション)
  によるもの。異なるAIモデルでの再現(Geminiなど)を試すことで、
  「AMP固有の価値」なのか「このモデル・この設計に特有の効果」なのかを
  切り分ける
