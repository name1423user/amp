# v1.0の目標: AI同士の会話実証

## 決定

v1.0は「**静的カタログを前提に、複数のAIエージェントがAMPのJSONだけで実際に多ターンの
会話を成立させ、そのログを英文で監査できる**」ことを達成条件とする。

handshake・動的語彙合意は対象外(判断1のまま)。第二の独立実装による相互運用性の検証も
対象外——これが判断書の言う「本当の実用化条件」だが、他者の実装という外部条件に依存し、
自分の手だけでは到達できないため。

## 背景: 今のギャップ

判断書 判断7「最初の実利用先はMAGI」は既に一度実行されている(M6, `m6-magi-findings.md`)。
しかしそこでやったのは「**人間**がMAGIの出力を読んでAMPのJSONに手で変換し、それを
`amp render`で英文化した」ことであって、**AI自身がAMPのJSONを生成してはいない**。

現状の`amp`は「JSON→英文」の片道変換ツールとしては完成しているが、「AIがAMPを読み書き
して会話する」というこのプロジェクトの本題(2026-09-13の議論)はまだ試されていない。
v1.0はこのギャップ、つまり**生成→送信→解釈→応答のラウンドトリップ**を1回でも実際に
回すところまでを指す。

## 達成条件(検証可能な形で)

1. 最低1つの複数ターン会話(3往復以上)が、人間が仲介してJSONを直接書くことなく、
   AIエージェント自身がAMPメッセージを生成して成立する
2. 会話が意味的に一貫している——受信側が`act`/`predicate`/`roles`を正しく解釈し、
   文脈に合った`act`で応答する(例: `request`→`commit`または`reject`、`query`→`inform`)
3. 会話終了後、`amp render`でログ全体を英文化でき、人間がそれを読んで会話の流れを
   誤解なく追える
4. 参加するAIエージェントは独立実装でなくてよい(判断7と同じ理由)。相互運用性の
   検証にはならないが、**生成/解釈のラウンドトリップ**の検証にはなる
5. 語彙(entity/type)は静的カタログとして事前に用意してよい

## スコープに含めない

- handshake / 動的語彙合意(判断1)
- 第二の独立実装との相互運用(達成後の次フェーズ)
- `time`/`location` role、命題の論理関係(and/or)、命題statusの区別 —
  ADR-024の基準どおり、この実証の過程で必要性が具体的に確認されたら都度追加する。
  先回りして実装しない

## 検証方法(候補・いずれか1つで達成とする)

- MAGIの3体合議にAMPを組み込み、3体が実際にAMPメッセージで主張・反論・収束を行う
- このセッションと別のAIエージェント(SendMessageで届く別セッション等)がAMPで
  多ターン往復する

**status: 達成 (2026-09-13)**。両方の検証方法を実施した。
- Phase 1(2者間往復): [`v1.0-roundtrip-verification.md`](v1.0-roundtrip-verification.md)
- Phase 2(MAGI 3体合議): [`v1.0-phase2-magi-verification.md`](v1.0-phase2-magi-verification.md)

(判断書が言う本当の相互運用性検証)に進む。
